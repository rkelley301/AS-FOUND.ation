PLC ↔ Instrument Block Diagrams

01 Why This Matters Now
⚡ Hook Up to now you've learned each piece in isolation: the physics, the wire, the drawing, the panel. But in the field, the question is almost never about one piece — it's about the whole loop. "Why isn't the flow reading right?" could be the transmitter, the wiring, the terminal, the I/O card, the PLC scaling, the logic, or the HMI. If you can't see the whole system, you can't troubleshoot it. A block diagram is how you see the whole system at a glance.
02 The Analogy

A block diagram is a relay race.

The signal starts in the field, gets handed off at each stage, and eventually ends up as an action on the other side. Each block is a runner. Each arrow is a handoff. If any handoff fails, the whole race fails — and the block diagram tells you which runner to look at.

03 Core Concepts

1. What a Block Diagram Actually Is

A block diagram is a simplified system view. Each block represents a device, a function, or a signal-processing step. Arrows show what flows between them. There are no wires, no terminal numbers, no pin details — just what each block does and how signal moves between blocks.

  • Blocks are rectangles with labels inside. The label describes the function, not the part number. "Transmitter," "A/D Converter," "PID Controller," "Valve."
  • Arrows show direction of signal flow. Almost always left to right for the process signal, with feedback drawn as a return path.
  • Signal labels on the arrows describe what's flowing: 4-20 mA, 0-10 V, digital bits, 0-100% CV, engineering units, etc.
  • No physical detail. A block diagram of a control loop doesn't care whether the wire goes through a junction box or a terminal strip — that's the wiring diagram's job.
  • Purpose: To understand the system architecture, identify where a fault could be, and communicate the design without needing to draw every detail.

2. The Universal Control Loop — Block by Block

Every process control loop — flow, pressure, level, temperature — has the same fundamental block diagram. Once you understand this one diagram, you understand every loop.

Universal control loop block diagram. Signal flows: Process → Transmitter → Terminal Block → AI Card → CPU (PID) → AO Card → Terminal Block → Valve → Process.

Read it left to right (forward path):

  • Process — the physical thing being controlled (flow, level, temperature, pressure). It has a process variable (PV) that we want to control.
  • Transmitter — the sensor that measures the PV and converts it to a 4-20 mA signal. It's the "eyes" of the loop.
  • Terminal Block — where the field wire meets the panel wire. Just a pass-through, but critical for isolation and test points.
  • AI Card — analog input card in the PLC. Converts the 4-20 mA analog signal into a digital number the CPU can process. This is the A/D conversion.
  • PLC CPU — the brain. Reads the digital value, scales it to engineering units, runs the PID algorithm, decides what the output should be, and sends a digital value to the AO card.
  • AO Card — analog output card. Converts the CPU's digital output value back into a 4-20 mA signal. This is D/A conversion.
  • Terminal Block — same as before, but on the output side. Pass-through to the field.
  • Final Element — the valve or actuator. Receives the 4-20 mA signal and moves to the commanded position. This is the "hands" of the loop.
  • Process — back to the start. The valve position affects the process, which changes the PV, which is measured by the transmitter, closing the loop.

The feedback path (dashed or drawn beneath):

  • The valve position changes the process.
  • The transmitter measures the new PV and sends a new 4-20 mA signal.
  • The PLC reads the new value and adjusts the output.
  • This continues indefinitely — that's what makes it a closed loop.

3. Signal Flow — How the Signal Changes Form

One of the most important ideas in system thinking: the signal changes form at every block. Understanding this is how you know where to measure and what to expect.

✓ Key Insight When troubleshooting, check the signal at each stage. If the transmitter reads 12 mA but the PLC sees 0 counts, the problem is between them (wiring, terminal, AI card). If the PLC sees the correct value but the output doesn't match the expectation, the problem is in the CPU logic or the AO card. The block diagram tells you where to look.

4. Analog vs Digital Signals — Two Different Worlds

Industrial instrumentation uses two broad signal types. Every loop you work on will involve one or both.

Analog Signals

  • Continuous values — any value in a range
  • 4-20 mA — the industry standard for instruments
  • 0-10 V — older systems, short distances only
  • RTD/TC — resistance or millivolt signals from temperature sensors
  • Requires A/D conversion at the PLC to become digital
  • Susceptible to noise — needs shielding and twisted pairs
  • Examples: flow, pressure, level, temperature, valve position

Digital Signals

  • Two states only — ON/OFF, 1/0, TRUE/FALSE
  • 24 VDC discrete — the standard for most PLC digital I/O
  • 120 VAC discrete — older systems, still common in motor controls
  • Dry contact — just a switch closure, no voltage
  • Already digital — no conversion needed for the CPU
  • Highly noise-immune at logic voltages
  • Examples: limit switches, pushbuttons, relays, solenoids, motor starters

5. Inside the PLC — The Blocks You Need to Know

A PLC is not one device; it's a system of modules on a common backplane. Here's what's inside the box:

Inside the PLC: power supply, CPU, I/O cards (analog and digital), and communication modules all share a backplane bus.
BlockFunction
Power SupplyConverts incoming AC (usually 120 VAC) to the DC voltages the CPU and cards need (5 VDC for logic, 24 VDC for I/O).
CPUThe processor. Runs the user program (ladder logic, function blocks), executes the scan cycle, manages memory, and coordinates all other modules.
AI Card (Analog Input)Receives 4-20 mA or other analog signals from field transmitters. Converts them to digital values (raw counts) for the CPU.
AO Card (Analog Output)Takes digital values from the CPU and converts them back to 4-20 mA signals for valves, positioners, or other final elements.
DI Card (Digital Input)Reads on/off states from field switches, pushbuttons, and contacts. 24 VDC present = logic 1; absent = logic 0.
DO Card (Digital Output)Drives on/off devices — relays, solenoids, indicator lamps, motor starters. Logic 1 = energize; logic 0 = de-energize.
Comm ModuleConnects the PLC to networks: Ethernet/IP, Modbus TCP, Profibus, etc. Enables communication with HMIs, SCADA, other PLCs, and smart field devices.
BackplaneThe internal bus that lets all modules talk to the CPU. Every module plugs into it.

6. The PLC Scan Cycle — Why It Matters

A PLC doesn't respond instantly. It executes a repeating cycle — the scan cycle — that determines how fast it can react to inputs and update outputs. Understanding the scan cycle is essential for understanding why PLC-controlled loops behave the way they do.

The PLC scan cycle repeats continuously — typically every 5-50 milliseconds. Everything the PLC does happens in this cycle.

What each step does:

  • Input Scan: The CPU reads the current state of every input card and stores those values in input memory. This is a snapshot — it doesn't change during the rest of the scan.
  • Program Execute: The CPU runs the user program (ladder logic, function blocks). It reads from input memory, does math and logic, and writes results to output memory.
  • Output Update: The CPU copies the output memory values to the output cards, which drive the physical outputs.
  • Repeat. The cycle starts over immediately. The speed at which this repeats is the scan time.
✓ Why This Matters The PLC can only "see" inputs once per scan. If a signal pulses for less than the scan time, the PLC might miss it entirely. This is why very fast events (like a short pulse from a flow meter) require either a high-speed counter module or dedicated hardware — the standard scan cycle can't catch them.

7. HART Communication — Digital on Top of Analog

Most modern 4-20 mA transmitters also support HART, which superimposes a digital signal on the same two wires. This doesn't interfere with the 4-20 mA signal — the analog current still drives the loop, and the digital signal carries extra information (diagnostics, calibration data, secondary variables).

  • HART signal is FSK (Frequency Shift Keying) — small AC frequencies added to the DC loop current.
  • Doesn't interfere with the 4-20 mA signal — the digital modulation is filtered out by the receiver.
  • Requires a HART communicator or HART modem — a handheld device or a PC with a HART modem.
  • Supports device configuration, diagnostics, and multi-variable readout — over the same two wires that carry the 4-20 mA signal.
  • Loop resistance matters: HART needs at least ~230 Ω of loop resistance to communicate properly. Very low-resistance loops may prevent HART communication.

8. Digital Fieldbus — When the Whole Signal Is Digital

Some systems go further: instead of an analog signal with digital on top, they use a pure digital fieldbus where the entire measurement is transmitted digitally. FOUNDATION Fieldbus, Profibus PA, and HART-IP are examples.

  • Advantages: Multiple variables from one device, faster diagnostics, multi-drop topologies (many devices on one cable), and remote configuration.
  • Disadvantages: More complex, requires special tools and training, harder to troubleshoot without specialized software.
  • Signal in the block diagram: The field signal to the PLC is digital from the start. The AI card might be replaced by a fieldbus interface module, but the block diagram concept is the same.

9. How to Draw a Block Diagram — Step by Step

Block diagrams are drawn from left to right, top to bottom, following the signal flow. Here's the systematic approach:

  • Identify the process variable and the final control element. What is being controlled (flow, level, temperature)? What device controls it (valve, motor, heater)?
  • List every device in the loop. Transmitter, junction box, terminal block, I/O card, PLC CPU, HMI, power supply, final element, etc.
  • Arrange them in signal flow order. Field on the left, PLC in the middle, HMI on the right. Feedback path drawn below or as a dashed line.
  • Draw boxes for each device. Label each box with its function (not its part number). Keep box size consistent.
  • Draw arrows between blocks. Label each arrow with the signal type — 4-20 mA, digital bits, 0-100%, physical PV, etc.
  • Add the feedback path. Close the loop: valve affects process, process affects transmitter, transmitter feeds back to PLC.
  • Annotate critical values. Range, setpoint, alarm limits, loop number, tag numbers. Keep it clean — don't overcrowd.
  • Review for clarity. Can someone unfamiliar with the loop understand it in 30 seconds? If not, simplify.

10. Describing the System — The Verbal Skill

Drawing is one skill. Describing the system in words is another — and it's what you'll be asked to do in meetings, on job sites, and in troubleshooting calls. A clear verbal description follows the same path as the block diagram:

  • Start with the process variable: "We're controlling the flow of cooling water on loop FIC-101, range 0-500 GPM."
  • Name the transmitter: "Flow transmitter FT-101 senses the differential pressure across an orifice plate and converts it to a 4-20 mA signal."
  • Trace the signal path: "The 4-20 mA signal goes through junction box JB-101, lands on terminal block TB1, and goes into analog input card AI-01, channel 3."
  • Explain the PLC action: "The PLC scales the raw count to engineering units, compares it to the setpoint of 250 GPM, and runs a PID algorithm that outputs a 4-20 mA signal from AO card AO-01."
  • Name the final element: "That signal drives flow control valve FV-101, which adjusts the cooling water flow to bring the process variable to setpoint."
  • Close the loop: "The loop is closed — every change in valve position changes the flow, which is picked up by the transmitter, and the cycle continues."
✓ Interview Question "Describe how a PLC controls a flow loop." If you can answer this in 60 seconds — clearly, in order, with the right terms — you'll do well in any I&C interview. Practice it out loud.

12. Redundant and Fault-Tolerant Configurations

Critical loops use redundancy to keep operating even if a component fails. Block diagrams show these configurations clearly.

  • Redundant transmitters: Two (or three) transmitters measure the same PV. The PLC uses voting logic (median, average, or 2-out-of-3) to determine the best value.
  • Redundant CPUs: Primary and backup CPUs run the same program. If the primary fails, the backup takes over without interrupting the process.
  • Redundant I/O cards: Primary and backup cards wired to the same field device. If the primary fails, the backup takes over.
  • Redundant power supplies: Two power supplies share the load. If one fails, the other picks up without a glitch.
  • Redundant networks: Two separate network paths. If one fails, the other carries the traffic.

Exercise D: Identify the Fault

Consider this scenario with the temperature loop from Exercise B:

  • TT-205 reads 180°F at the transmitter (verified with a multimeter measuring loop current).
  • The AI card channel 5 shows 45°F in the PLC software.
  • The PID output is stuck at 100% (valve fully open).
  • The valve is fully open, but the tank never reaches setpoint.

Where is the fault likely located? Use the block diagram to reason through it:

  • The transmitter reads 180°F correctly, so the transmitter is fine.
  • The AI card reads a different value, so the problem is between the transmitter and the AI card.
  • Possible causes: wiring fault between transmitter and TB, bad terminal connection, wrong AI channel configured, or scaling error in the PLC.
  • The valve is fully open and the temperature isn't rising — that suggests the process has reached equilibrium or the steam supply is insufficient.

Write down the specific steps you'd take to isolate the actual fault.
